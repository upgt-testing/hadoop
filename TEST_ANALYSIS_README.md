# YARN Restart Test Results Analysis

This directory contains Python scripts for analyzing YARN restart test results generated by the Restart Testing Framework.

## Overview

The restart tests generate Surefire XML reports in a timestamped output directory. These analysis scripts parse those reports, extract test results, group failures by normalized stack traces, and generate summary reports.

## Generated Scripts

### 1. `analyze_restart_test_results.py`

**Main analysis script** that parses all surefire XML reports and generates comprehensive analysis.

**Usage:**
```bash
python3 analyze_restart_test_results.py <test_output_dir>
```

**Example:**
```bash
python3 analyze_restart_test_results.py restart-test-output-20251203-143743
```

**Output Files:**
- `<dir>_analysis_report.txt` - Detailed text report with:
  - Overall summary (pass/fail/error counts)
  - Failures grouped by normalized stack trace
  - Full details of each failure

- `<dir>_analysis_report.json` - JSON format for programmatic analysis

**Features:**
- Parses all TEST-*.xml files in the output directory
- Extracts test class, method, status, timing
- Parses restart configuration (position, target, mode) from directory names
- Normalizes stack traces by:
  - Removing line numbers (e.g., `.java:123` → `.java`)
  - Truncating after test framework boilerplate
- Groups failures by normalized stack trace + failure type
- Shows which tests are affected by each failure pattern

### 2. `generate_failure_summary.py`

**CSV generator** for easy viewing in spreadsheet tools.

**Usage:**
```bash
python3 generate_failure_summary.py <json_report_file>
```

**Example:**
```bash
python3 generate_failure_summary.py restart-test-output-20251203-143743_analysis_report.json
```

**Output Files:**
- `<dir>_failure_groups.csv` - Summary of failure groups
  - Group number, occurrence count, failure type/message
  - Affected test classes and methods
  - Stack trace preview

- `<dir>_all_results.csv` - Detailed results for every test
  - One row per test execution
  - Includes: class, method, status, time, restart config, failure details

### 3. `generate_module_summary.py`

**Module-level summary** showing results by module.

**Usage:**
```bash
python3 generate_module_summary.py <json_report_file>
```

**Example:**
```bash
python3 generate_module_summary.py restart-test-output-20251203-143743_analysis_report.json
```

**Output:**
- Console output showing:
  - Test counts by module (passed/failed/errored)
  - Overall summary across all modules
  - Top 10 failure patterns

### Key Findings:

1. **Adapter Issues:** Many HA tests fail because there's no adapter registered for `MiniYARNClusterForHATesting`. This needs a custom adapter implementation.

2. **Disk Failure Tests:** Tests involving disk failures are failing consistently, suggesting issues with how disk state is preserved/restored across restarts.

3. **Container Management:** Several tests fail with IndexOutOfBoundsException, indicating container lists are empty after restarts when they shouldn't be.

4. **Timeouts:** Some proxy tests are timing out, possibly due to restart delays or hanging operations.

## Stack Trace Normalization

The normalization process ensures similar failures are grouped together:

### Rules:
1. **Remove line numbers:** `TestFile.java:123` → `TestFile.java`
2. **Truncate after test framework:** Stack traces are cut at common JUnit/Surefire entry points

### Why This Matters:
- Line numbers change as code evolves
- Framework boilerplate is identical across tests
- Grouping by normalized traces shows the **root cause** rather than individual occurrences

### Example:

**Before normalization:**
```
at TestClass.method(TestClass.java:45)
at TestClass.method(TestClass.java:67)
at TestClass.method(TestClass.java:89)
```

**After normalization:**
```
at TestClass.method(TestClass.java)
```

All three become the same group, revealing they share a common failure mode.

## File Formats

### Surefire XML Format
The scripts parse standard Surefire/JUnit XML test reports:
```xml
<testsuite name="..." tests="1" failures="0" errors="1">
  <testcase classname="org.example.Test" name="testMethod" time="2.5">
    <error type="java.lang.Exception" message="...">
      <![CDATA[stack trace here]]>
    </error>
  </testcase>
</testsuite>
```

### JSON Report Schema
```json
{
  "summary": {
    "total": 294,
    "passed": 105,
    "failed": 18,
    "errored": 171,
    "skipped": 0
  },
  "results": [
    {
      "testClass": "...",
      "testMethod": "...",
      "status": "FAIL|PASS|ERROR|SKIPPED",
      "time": 2.5,
      "position": "after_cluster_start",
      "target": "resourcemanager",
      "mode": "CRASH",
      "failureType": "java.lang.Exception",
      "failureMessage": "...",
      "stackTrace": "..."
    }
  ],
  "failureGroups": [
    {
      "failureType": "...",
      "count": 15,
      "normalizedStackTrace": "...",
      "failureMessage": "...",
      "affectedTests": [...]
    }
  ]
}
```
